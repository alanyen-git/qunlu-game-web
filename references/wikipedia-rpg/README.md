# 維基百科 RPG 設計參考庫

> 建立日期：2026-09-22  
> 用途：作為《群陸旅誌》世界觀、角色、職業、戰鬥、探索、任務、NPC、成長與管理 AI 的「設計參考索引」。  
> 原則：只保留維基百科公開頁面的來源連結、事實性摘要與抽象設計模式；不鏡像全文、不直接搬用角色、劇情、專有名詞、技能名稱、數值或受保護素材。

## 使用規則

1. **可借鑑系統結構，不直接複製 IP 內容。** 例如可借鑑「職業 + 次職業」、「技能使用式成長」、「弱點破防」等抽象結構，但需重新命名、重新平衡、重新嵌入《群陸旅誌》的世界規則。
2. **《群陸旅誌》既有規格優先。** 世界 F–S 層級、九元素、冒險者／戰鬥職業／副職業分離、經濟與市場模型、活世界循環、死亡復活、負重、技能經驗值等既有規則不得被參考來源覆蓋。
3. **來源只作研究索引。** 若後續要導入機制，必須先經資料庫查重、世界觀一致性檢核、名稱自然化與平衡測試。
4. **避免專有設定移植。** 不把特定世界地名、組織、角色、神器、招式、怪物名稱直接加入正式資料庫。
5. **維基百科授權注意。** 本資料庫只做摘要與來源鏈結；需要引用原文時應回到原頁並遵守其授權與署名要求。

## 1. 龍與地下城（Dungeons & Dragons）

### 維基百科來源
- https://en.wikipedia.org/wiki/Dungeons_%26_Dragons
- https://en.wikipedia.org/wiki/Dungeons_%26_Dragons_gameplay
- https://en.wikipedia.org/wiki/List_of_Dungeons_%26_Dragons_rulebooks

### 設定／資料重點
- 典型奇幻桌上角色扮演框架，由玩家角色組成冒險隊伍，主持者負責世界、NPC、事件與規則裁定。
- 角色通常由能力值、物種／種族、職業、背景、技能、專長、裝備與角色立場等模組組成。
- 冒險、戰鬥、探索、社交、環境與魔法都在同一套規則框架下被處理。
- 世界可採「核心規則 + 多個戰役設定」方式擴充，不需要所有地區共享相同文化與權力結構。

### 系統重點
- d20 類型檢定：能力、技能、攻擊、豁免等使用機率結果處理不確定行動。
- 能力值是底層角色屬性，職業與技能在其上形成差異化。
- 職業等級提供新能力；專長可作為有前置條件的額外成長節點。
- HP、護甲／防禦、攻擊、傷害、豁免、技能等形成可拆分的戰鬥／冒險判定層。
- 經驗、財富、魔法物品與任務成果共同推動角色成長。

### 對《群陸旅誌》的可借鑑方向
- 將管理 AI 明確視為「世界裁定層」，負責規則、NPC、事件與環境結果，但不得任意越過資料庫。
- 強化「前置條件」資料欄位：技能、專長、流派、裝備、職業晉升皆能共用。
- D20 保留為風險行動的統一判定語言，但仍以本專案既有單次擲骰與世界層級規則為準。
- 將「戰役設定」概念轉為不同政治體、文化圈與區域規則包，避免所有地區同質化。

## 2. 柏德之門 3（Baldur's Gate 3）

### 維基百科來源
- https://en.wikipedia.org/wiki/Baldur%27s_Gate_3

### 設定／資料重點
- 建立在 D&D 第五版規則與 Forgotten Realms 世界之上，將桌遊規則轉譯為電腦 RPG。
- 強調隊友、對話選擇、分支結果、探索互動與環境解法。
- 職業與子職業提供明顯遊玩定位差異，隊伍組合會改變可用手段。

### 系統重點
- 核心檢定以 d20 為基礎，並有優勢／劣勢等機率修正方式。
- 單人與多人都允許隊員在不同空間行動，強調「同一世界狀態下的多角色行為」。
- 類別、子類別、法術、行動與額外行動等被清楚拆層。
- 數位化時會對桌遊規則做適度轉譯，而非機械照搬。

### 對《群陸旅誌》的可借鑑方向
- 對話、探索、戰鬥都共享同一個「條件 → 檢定 → 結果 → 世界狀態」流程。
- NPC／隊友應能保存好感、信任、恐懼、立場、已知情報與事件記憶。
- 職業介紹 UI 應直接顯示定位、專長武器、技能特色與成長方向。
- 環境／事件檢定應允許多種解法，而不是每個委託只存在單一路徑。

## 3. 太空戰士／Final Fantasy 系列

### 維基百科來源
- https://en.wikipedia.org/wiki/Final_Fantasy
- https://en.wikipedia.org/wiki/Recurring_elements_in_the_Final_Fantasy_series

### 設定／資料重點
- 主系列多採獨立世界、獨立角色與獨立劇情，但保留一批可辨識的系列級設計母題。
- 奇幻與科技可在不同作品以不同比例混合。
- 隊伍角色通常有明確功能定位，世界危機與角色個人議題並行。
- 常見母題包括大型世界能源／象徵物、召喚型存在、飛行交通工具與反覆出現的系統概念，但各作會重新詮釋。

### 系統重點
- 隊伍制 RPG，常見戰鬥指令包含攻擊、魔法、道具與角色專屬能力。
- 多作以經驗值／等級與裝備提升能力。
- 職業／Job、元素、狀態、魔法、召喚等可作為模組化戰鬥規則。
- 系列在回合制、ATB、即時與動作化之間持續調整，但角色定位與資源管理仍是核心。

### 對《群陸旅誌》的可借鑑方向
- 建立「跨地區共通規則 + 各政治體獨有詮釋」：九元素相同，但魔法教育、裝備文化、召喚／契約方式可不同。
- 職業不是只有數值差異，必須有資源循環、節奏、隊伍定位與技能特色。
- 高階裝備／技能可透過素材、前置、任務或傳承形成可追蹤的取得鏈。
- 系列母題的做法可轉成《群陸旅誌》自己的 recurring motifs，但不能直接使用既有 IP 的象徵物與專名。

## 4. 上古捲軸（The Elder Scrolls）系列

### 維基百科來源
- https://en.wikipedia.org/wiki/The_Elder_Scrolls
- https://en.wikipedia.org/wiki/The_Elder_Scrolls_V%3A_Skyrim
- https://en.wikipedia.org/wiki/The_Elder_Scrolls_IV%3A_Oblivion

### 設定／資料重點
- 核心舞台為 Nirn 世界的 Tamriel 大陸，各省份有明確種族、歷史、文化與政治差異。
- 大陸級設定並不代表所有區域都完全已知；其他大陸與異界可保留有限可靠資訊。
- 城鎮、野外、洞穴、地下城、堡壘、村落等構成自由探索網路。
- 玩家可加入不同派系並推進各自任務鏈，派系不必依附主線。

### 系統重點
- 開放世界、非線性探索與大量支線。
- 多代作品採「技能使用越多，技能越成長」的角色發展方式；Skyrim 再由技能成長帶動角色等級。
- 戰鬥、魔法、潛行技能並列，角色不一定被固定職業完全鎖死。
- 製作、鍛造、附魔、煉金與探索互相供應資源。
- NPC、派系、城鎮與地圖發現形成長期探索回饋。

### 對《群陸旅誌》的可借鑑方向
- 既有「技能經驗值 Lv1–10」可強化為使用式成長，但需加入每日／區域／難度上限避免刷取。
- 城鎮規模、政治體文化與資源分布應真正影響可學技能、商店庫存、委託、素材與 NPC 專業。
- 派系任務鏈應可獨立運作並與活世界循環互相改變狀態。
- 大陸資訊應區分「玩家已知、角色已知、世界真實資料」三層，避免角色全知。

## 5. 超時空之鑰（Chrono Trigger）

### 維基百科來源
- https://en.wikipedia.org/wiki/Chrono_Trigger

### 設定／資料重點
- 故事跨越多個時代，同一世界在不同年代呈現不同文明、地貌與政治狀態。
- 過去行動可影響未來，時間線本身是任務與世界狀態的一部分。
- 同一核心威脅在不同年代留下不同痕跡，使世界事件具有長期因果。

### 系統重點
- 地圖上可見敵人，接觸後直接進入戰鬥，降低純隨機遭遇。
- ATB 類戰鬥由角色速度決定行動節奏。
- Tech 技能可由不同角色組成雙人／三人合體技。
- 多結局依玩家何時、如何完成關鍵事件而改變。
- New Game Plus 讓既有成長可進入新的流程。

### 對《群陸旅誌》的可借鑑方向
- 活世界事件應保存「前因 → 變化 → 後果」，而非每次進城重置。
- 隊友之間可建立「協同技能」資料層，前置條件包含關係、技能等級、武器與站位／狀態。
- 地區狀態可保存歷史版本，例如災害前後、戰爭前後、政權更替前後。
- 不導入真正時間旅行也能借鑑其因果設計：玩家早期決策在之後產生可追溯後果。

## 6. 聖火降魔錄（Fire Emblem）系列

### 維基百科來源
- https://en.wikipedia.org/wiki/Fire_Emblem

### 設定／資料重點
- 常見為中世紀奇幻國家、戰爭、王權、軍隊、血統、信仰與龍／超自然力量交織。
- 角色不只是戰鬥單位，也透過支援關係與劇情形成長期連結。
- 不同作品多有獨立大陸或時代，但保留戰術 RPG 與角色關係的系列核心。

### 系統重點
- 格狀戰術地圖、職業、移動範圍、武器、能力值與角色技能共同構成戰術差異。
- 角色執行攻擊、治療等行動可取得經驗。
- 職業可晉升或轉換，部分作品需要特定道具或條件。
- 支援關係能提供戰鬥加成並解鎖角色互動。
- 經典模式具有永久死亡風險，後期作品也提供較寬鬆模式。
- 不同作品對武器耐久、修理、強化採不同設計。

### 對《群陸旅誌》的可借鑑方向
- 隊友資料不能只記戰力；應保存關係、協同、共同事件與支援效果。
- 職業晉升應結合前置能力、導師／組織、任務、證明與資源，而非單純達等自動轉職。
- 裝備耐久與維修可作為經濟模型的可選深度，但需避免增加無意義操作量。
- 死亡／重傷後果可分層，與現有 3 次復活機制、教會與特殊技能整合。

## 7. 歧路旅人（Octopath Traveler）

### 維基百科來源
- https://en.wikipedia.org/wiki/Octopath_Traveler

### 設定／資料重點
- 由多名出身不同地區、職業與個人目的的冒險者構成，多條個人旅程在同一世界並行。
- 每個角色都有與 NPC 互動的 Path Action，並依角色定位提供不同解法。
- 城鎮聲望會受到高風險互動影響。

### 系統重點
- 角色有固定主職業，並可取得可切換的副職業。
- NPC 互動可包含挑戰、打聽、取得物品、引導／招募等不同功能。
- 部分互動以等級／金錢等可靠條件判定，部分則帶有失敗與聲望風險。
- 戰鬥核心為「弱點 + Shield Points + Break」與「Boost Points」：先用弱點削減防護，再集中資源爆發。

### 對《群陸旅誌》的可借鑑方向
- 現有副職業可強化成「主職定位穩定，副職提供可調整模組」，但仍遵守最多 2 個副職業的專案規則。
- NPC 互動依職業／副職業／名聲解鎖不同按鍵，讓生活職業也能改變冒險流程。
- 城鎮名聲、犯罪、黑市、拍賣行與情報系統可共用同一個「合法／灰色／非法」互動風險框架。
- 可借鑑 Break 的節奏感，但應改造成《群陸旅誌》自有的架勢／防護／弱點機制，不能照抄名稱與數值。

## 8. 聖劍傳說（Mana）系列

### 維基百科來源
- https://en.wikipedia.org/wiki/Mana_%28series%29

### 設定／資料重點
- 系列多為奇幻動作 RPG，各作品之間通常不是單一路線的直接續篇。
- 常反覆使用象徵性世界母題，使不同作品即使世界與角色不同仍具有系列辨識度。
- 早期多作以世界樹、聖劍及爭奪其力量的衝突作為反覆母題；這些屬原作 IP 設定，只能作「系列母題設計法」研究，不得移植。
- 角色、怪物、藝術概念與音樂主題在不同作品可用不同版本重新詮釋。

### 系統重點
- 主要作品多屬動作 RPG，強調即時移動、武器、魔法、隊伍與場景探索。
- 系列會跨不同玩法類型，但仍以核心世界意象維持辨識度。
- 各作具高度機制變化，適合作為「共同世界規則下允許不同地區／作品機制表現」的參考。

### 對《群陸旅誌》的可借鑑方向
- 建立《群陸旅誌》自己的系列級母題：例如九元素循環、古代遺產、跨國公會網、世界事件痕跡等，但完全使用原創名稱與歷史。
- 同一類生物／組織可有地域變體，但要保留資料庫共用底層 ID 與生態邏輯。
- 不同政治體可採不同戰鬥文化與生產方式，仍接在同一套底層資源／技能／市場規則。

| 戰鬥節奏 | Octopath、Chrono、FF | 弱點、資源累積、行動節奏 | 自有防護／架勢、技能資源、九元素 |
| 探索 | TES、D&D、BG3 | 非線性地圖、環境解法、多路徑 | 城鎮／野外／地下城、事件調查 |
| NPC 互動 | BG3、Octopath、TES | 對話、職業互動、聲望風險 | 名聲、黑市、情報、委託、派系 |
| 活世界 | TES、Chrono、D&D | 世界狀態、事件因果、區域差異 | 世界事件鏈＋城鎮狀態＋傳聞＋NPC反應 |
| 經濟／製作 | TES、D&D、FF | 裝備、素材、製作、稀有物取得鏈 | 市場波動、限量庫存、採集上限、鍛造／料理 |
| 世界結構 | TES、FF、Mana、FE | 地域文化差異、系列母題、多世界／多政治體 | 政治體、文化圈、九元素、世界層級 |
| 多主角敘事 | Octopath、FE、Chrono | 個人線並行、事件交錯、角色不是唯一主角 | 沙盒 NPC、隊友個人事件、地區事件鏈 |

# 後續導入規範

任何從本參考庫延伸的新功能，先依序通過：

1. **查重**：現有資料庫是否已有同功能／同概念。
2. **世界觀一致性**：是否符合《群陸旅誌》的政治體、世界層級、九元素、技術／魔法普及度。
3. **資料結構**：建立唯一 ID、類型、等級、前置、來源、地區、價格／重量／掉落／產出等必要欄位。
4. **經濟閉環**：素材來源、掉落、商店、收購、製作與任務需求一致。
5. **活世界接入**：是否會影響城鎮狀態、NPC、傳聞、委託、派系或世界事件。
6. **數值平衡**：不得因參考作品的高爆發設計破壞 F–S 世界層級與 Lv1–99 成長曲線。
7. **IP 安全**：重新命名、重新設計敘事與美術概念，避免直接複製角色、專名、文本、地圖與具辨識度內容。

- 資料庫／生成器若要使用這些參考，應讀取「design_patterns」與「project_mapping」，不應把來源頁面的專有名詞當成生成字庫。
